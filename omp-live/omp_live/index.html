Open Memory Protocol · v0.2 editors’ draft
The OMP format: one record per memory
Every store keeps memory its own way and shares it in this one shape. In the minimal record this demo uses, four fields are required; the rest travel when a store has them. Unknown fields are preserved. Read the spec


OMP record


  1. Each store keeps its own format. Files stay files, the graph stays a graph. Nobody writes a converter for every pair.
  2. A change leaves as one OMP record with its identifier, body, version, checksum and provenance.
  3. Every other store imports it and writes a receipt: accepted, transformed, conflict or rejected.
  4. Across machines, identity holds. The manifest’s origin plus the identifier name a memory everywhere, and a forget travels as a tombstone so old copies can’t bring it back.
The record


identifierStable id. With the manifest’s origin it is the global identity, so it survives renames and round trips.


media_typeFormat of the body, e.g. text/markdown.


bodyThe memory itself, as a string. Markdown links stay in the text.


attributesAn object for any other metadata. This demo keeps the search embedding here.


title · tagsHuman labels.


pathA mutable location, like a folder. Moving a note changes its path, not its identity.


linksTyped edges: target, optional rel such as supersedes.


provenanceAppend-only list of contributors: who authored, instructed, imported or edited.


version · checksumA version number and a hash of the canonical record, used to detect change and conflicts.


valid_untilExpires a memory without deleting it.


The export folder


omp-export/
├─ manifest.json   protocol_version, origin, profiles
├─ memories/       one JSON record per memory
├─ revisions/      earlier versions, kept
├─ tombstones/     forgotten ids: when, who, why; never content
├─ conflicts/      parked edits waiting for a person
└─ receipts/       what each import did
