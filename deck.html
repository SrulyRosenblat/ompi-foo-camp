No identity

Nothing says two copies are the same memory. Copy twice and you have two.

With OMP: one global key per memory, so a copy is recognized as a copy and a move can finish.

No provenance

Did you say it, or did a model infer it from a lockfile? After a copy, nobody can tell.

With OMP: each memory lists who contributed and when it was learned, and that list travels with it.

No lifecycle

Delete it in one tool and an old backup puts it straight back in another.

With OMP: a forget leaves a tombstone, so the next tool refuses to resurrect it from an older export.

Every harness already does memory. Each picked its own file, its own layout and its own rules for what goes in, and none of them can read the others' memory.

Don't read the list; let it sit. Ask which of these people have in their own repos right now. The point isn't that any one format is bad — it's that nothing ties them together. Three missing things: identity, provenance, lifecycle. Every later slide maps to one of those three.
02 · Why a shared format

A converter for every pair of tools, or one import and one export per tool.

132one-way converters,
each written for one pair
24adapters: one import
and one export per tool
12 = the coding-agent harnesses our ACP memory-server prototype already reads (Claude Code, Codex, goose, Cursor, Cline, Roo, Kilo, Zed, Gemini CLI, Qwen Code, Continue, Aider).

With pairs, the two biggest vendors decide whether you can leave. With a shared format, one adapter joins the whole network.

Drag the slider. n(n−1) one-way converters vs 2n adapters. Then read the foot line: the count matters less than who writes the converters, and who therefore decides whether you can leave.
03 · The object · §2–3

A memory is metadata plus a body. Three fields are required.

{
  "identifier": "MEMORY.md",
  "media_type": "text/markdown",
  "created_at": "2026-10-14T00:00:00Z",
  "body": "The user prefers concise answers."
}

The smallest conforming memory (Appendix C). No provenance means author unknown — a receiver MUST NOT read it as the user's own words.

FieldTierWhy it travels
identifierrequiredStable across versions. With origin, a global key.
media_typerequiredMarkdown, JSON, HTML, CSV, XML… not an ontology.
created_atrequiredWhen the system learned it.
valid_from / valid_untiloptionalWhen it's true. valid_until may be in the future.
provenanceauditEveryone and everything that contributed.
version · checksumauditOpaque version + declared comparator; integrity hash.
scopeACLTags access policy attaches to. Set by the system, never the agent.
path · title · tags · stuboptionalFolder structure is progressive-disclosure information.
evidence · linksoptionalWhy to believe it · how it relates to other memories.
anything elsepreservedUnknown fields MUST survive export.
The two-time-axis distinction is the one people miss: created_at = when the system recorded it; valid_from = when it became true in the world. "Status updates move to Friday" might be recorded Sep 15 but valid from Sep 15 or retroactively. Tier assignments are editors' proposals, except version and updated_at which were read back on Oct 14. The unknown-fields rule is what lets vendors innovate without breaking the round trip.
04 · Live · files in

A pile of markdown files becomes one export in the standard format.

→
  1. Each file becomes one memory.
  2. Front matter, if any, becomes metadata. Unknown keys are kept.
  3. identifier comes from the path. created_at from front matter or the file's date.
  4. A manifest gives the whole export one origin.
AI model · not neededEmbeddings · not needed

Splitting one long CLAUDE.md into separate memories would need a model. This step doesn't.

Ask for a volunteer to AirDrop a CLAUDE.md, AGENTS.md or a folder of notes and drop it anywhere on the deck. Their files land in the pile and convert one at a time: each memory opens to show every field (required ones in orange), then folds into a row. Click any row to reopen it. Nothing here is clever: one file, one memory, metadata from front matter, dates from the file. That's the point of the minimal profile: a folder of markdown gets there with no model. Export ⤓ downloads the result.

    06 · Live · one memory, four stops

    Four systems, two ways to pass one memory along.

    A converter for each pair of systemskeeps only what both sides share
    One shared format (OMP)every system reads and writes the same record
    Same memory, two copies, same route. Top: a hand-written converter between each pair of systems. It can only carry what both sides have a slot for, so on the very first hop we lose who said it, when, who may see it, its version, its source, and its identity. Two hops later it is one bare sentence in a text file. Bottom: the shared format. Every field arrives, and each system stamps itself in as it goes, so you can still trace the full path at the end. The next slide puts two stores face to face.

    dashed border = this demo’s own choice, not the spec
    Two stores that have never met: Ledger on the left keeps everything and insists on checksums; Notebook on the right is a plain notes app. Watch the middle lane. Each message that crosses comes back with a receipt, and the receipt is the point. The image is refused, not quietly dropped. The note with no checksum stays home, because a move never deletes until the other side has it. Both sides edit the same memory; the spec does not pick a winner, so both stay visible. A forget request carries no content, and the old copy that comes back is blocked. Dashed items are our choices, not the spec’s.
